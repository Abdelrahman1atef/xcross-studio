# Implementation Plan: `xcross inspect` — machine-readable IPA/app report

**Branch**: `001-inspect` | **Date**: 2026-11-01 | **Spec**: [spec.md](spec.md)

**Input**: Feature specification from `specs/001-inspect/spec.md`

## Summary

Add a top-level, read-only `xcross inspect <ipa|app> [--json] [--normalize]` command that reports what is really
inside an iOS app bundle. The report covers the bundle's Info.plist, every executable's architectures, signature kind
and embedded entitlements, the provisioning profile summary, icons, `Assets.car` and the launch screen, frameworks and
app extensions. Output is either a deterministic JSON document (schema v1, [contracts/inspect.schema.json](contracts/inspect.schema.json))
or a short ✔/✖ summary.

Approach: a new workspace package `packages/studio_ext` holds small read-only parsers: an IPA/`.app` source, a plist
reader, a Mach-O fat/thin reader, a code-signature SuperBlob reader and a BER/CMS profile reader. They feed an
`InspectReport` model, which goes through a deterministic ASCII-only JSON encoder, an optional normaliser and a
human-readable summary. The command is registered at the CLI composition root (`runner.dart`) with a few `// studio:`
seam lines. The ADK/xcross readers that already exist cannot be reused: they are `@internal`, writer-oriented, or they
reject fat binaries and BER input ([research.md](research.md) R2). No new third-party dependency is needed.

## Technical Context

**Language/Version**: Dart, workspace SDK constraint `^3.10.0` (local toolchain 3.13.7; CI uses Dart stable)

**Primary Dependencies**: `archive` 4.5.2 (zip streaming), `propertylistserialization` 1.5.0 (binary and XML plists),
`crypto` (input sha256), `args`, `path`, `meta`, `cli_kit` (workspace; `HostFileSystemInterface`, `CliError`). All are already resolved in
`pubspec.lock`, so there are no new third-party packages.

**Storage**: N/A (reads the input only; writes nothing)

**Testing**: `package:test`. Synthetic fixture bundles are built in code (`test/support/fixture_builder.dart`).
Committed golden JSON lives in `test/goldens/` (regenerate with `UPDATE_GOLDENS=1`). An opt-in real-IPA test runs
when `STUDIO_INSPECT_IPA=<path>` is set.

**Target Platform**: Windows and Linux hosts (first-class). macOS also runs in the existing CI matrix.

**Project Type**: CLI feature delivered as a Dart library package, consumed by the `xcross` executable

**Performance Goals**: inspect a 20 MB IPA in < 3 s on a typical laptop (SC-001)

**Constraints**: read-only and offline (FR-006); byte-identical `--json` output on Windows and Linux (FR-007); no
secrets in output (FR-004); peak memory ≈ the largest single zip entry, never the whole IPA (edge case "> 500 MB");
must pass `dart analyze --fatal-warnings` with the `repo_analyzer` architecture rules

**Scale/Scope**: one command, ~12 library files, about 1.5–2.5 kLOC including tests; 3 golden fixtures

No open clarification items remain; every unknown is resolved in [research.md](research.md).

### Source Code (repository root)

```text
packages/studio_ext/
├── pubspec.yaml                         # name: studio_ext, publish_to: none, resolution: workspace
├── analysis_options.yaml                # include: ../../analysis_options.yaml
├── lib/
│   ├── shared/inspect/
│   │   └── inspect_command.dart         # public: Command<void> "inspect", flags, output, error mapping
│   └── src/shared/inspect/              # all @internal
│       ├── inspect_source.dart          # IpaSource (archive InputFileStream) / AppDirectorySource
│       ├── inspector.dart               # walks the bundle → InspectReport
│       ├── plist_reader.dart            # format sniff, print-silenced parse, plist → JSON value
│       ├── macho_reader.dart            # fat/thin, 32/64-bit, arch names, LC_CODE_SIGNATURE
│       ├── code_signature_reader.dart   # SuperBlob, CodeDirectory, entitlement blobs, CMS blob
│       ├── ber_reader.dart              # BER/DER walker (definite + indefinite length)
│       ├── profile_reader.dart          # embedded.mobileprovision → ProfileSummary (redacted)
│       ├── bundle_resources.dart        # icons, Assets.car, launch screen, storyboards
│       ├── inspect_report.dart          # report model + ordered toJson
│       ├── report_json.dart             # deterministic ASCII-only JSON encoder
│       ├── report_normalizer.dart       # --normalize
│       ├── human_summary.dart           # ✔/✖ summary
│       └── inspect_failure.dart         # fatal error: code, message, hint
└── test/
    ├── support/fixture_builder.dart     # synthetic Mach-O, signatures, profiles, plists, .app, .ipa
    ├── goldens/                         # unsigned_v209.json, adhoc_push.json, profile_appex.json
    └── shared/inspect/                  # *_test.dart (see AC map)

packages/xcross/test/cli/inspect_registration_test.dart   # command registered; inspect --json owns stdout
```

**Structure Decision**: a single new library package inside the existing Dart workspace, laid out to satisfy
`repo_analyzer`. The command class is public under `lib/shared/` so the xcross composition root can import it without
a deep `lib/src` import. Parsers are `@internal` under `lib/src/shared/`. File access goes only through the injected
cli_kit `HostFileSystemInterface`, and output goes only through an injected `write` callback (no `stdout` or
`Platform` in library code). There is no barrel file and no `export`.

## Complexity Tracking

| Violation | Why Needed | Simpler Alternative Rejected Because |
|---|---|---|
| Own read-only parsers (plist wrapper, Mach-O, SuperBlob, BER/CMS) partly duplicate ADK/xcross internals (Principle VII prefers reuse) | The existing readers are `@internal` in `apple_developer_kit/lib/src` and `xcross/lib/src`. `MachOLayout` rejects fat, 32-bit and non-arm64 binaries, `DerReader` rejects the BER indefinite-length encoding profiles may use, and the signature code there only writes. The spec's assumption already allows this fallback. | Exporting the ADK readers would mean editing many upstream files and dropping `@internal`, against Principle I. They also could not read fat or BER input without further upstream changes. |
