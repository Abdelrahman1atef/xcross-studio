# XCross Studio Constitution

XCross Studio is an open-source fork of [xcross](https://github.com/arxdeus/xcross) plus a desktop GUI for
**Windows and Linux**, so a Flutter developer can create, build, sign and install a complete iOS app on a real
iPhone without a Mac.

## Core Principles

### I. Minimal Diff From Upstream
Fork features live in new files (package `packages/studio_ext`, app `apps/studio`). Upstream files are changed only
at small, documented seams marked with a `// studio:` comment (composition root, `FlutterPacker` step injection,
one-to-five-line hooks). Generally useful fixes are proposed upstream first and cherry-picked; the fork copy is
removed once upstream merges it. Every upstream release tag is merged into `main` (no rebasing public history).

### II. Never Redistribute Apple Material (NON-NEGOTIABLE)
The project never ships, hosts, downloads on the user's behalf, or caches for others any Apple SDK, Xcode archive,
DeveloperDiskImage, or other Apple-licensed binary. Users supply their own `Xcode.xip`. Code paths that would
auto-download DDIs from third parties are disabled. User-facing surfaces state "not affiliated with Apple" and do
not use Apple logos.

### III. Fail Fast, Never Skip Silently
Every unsupported input (podspec-only plugin, asset catalog, storyboard, entitlement, iOS version, host service)
produces a warning or error with a stable code and a concrete fix hint. Checks that can run before a long build
(device iOS version, host device service, toolchain/PATH sanity) run before it.

### IV. The CLI Is the Product
All build, sign, install and device logic lives in the CLI. The GUI is a thin shell: it runs the `xcross` binary as
a subprocess and consumes the versioned `--json` NDJSON event stream. The GUI never imports `@internal` xcross code
and never re-implements build logic.

### V. Windows and Linux Are Equal First-Class Hosts
Every feature works and is tested on both Windows and Linux. OS-specific code stays behind the existing
`host/windows` / `host/linux` split in the CLI and a single `HostPlatform` interface in the GUI. WSL is not a
supported host for device work; native hosts are.

### VI. Test-First With Device Evidence
Every acceptance criterion (numbered `AC-NNN-n`) maps to an automated test whose name contains the AC id, or to a row
in the feature's `device-check.md`. Golden IPA tests diff `xcross inspect --json` output; the same fixture built on
Windows and Linux must produce identical normalised output.

### VII. Simplicity
Implement the smallest change that satisfies the acceptance criteria. Prefer reusing existing xcross components
(`BundleSigner`, `MachOSigner`, `AscProvisioning`, `AppExtensionBuilder`, `PymdDevices`) over new ones. New
dependencies need a written justification in the feature's `plan.md`.

### VIII. License and Credential Hygiene
The fork and GUI remain AGPL-3.0: modifications are marked, notices kept, full source published with every binary.
Third-party licences are recorded in `NOTICE`. Credentials (Apple ID session, App Store Connect keys) are stored only
in the OS credential store or xcross's own protected files, never logged, never included in bug reports, and there
is no telemetry.

## Legal & Licensing Constraints

- The Xcode and Apple SDKs Agreement restricts use of the SDK to Apple-branded hardware. This risk cannot be removed;
  it is mitigated by Principle II, a first-run acknowledgement in the GUI, and clear documentation.
- RunnerShim code generated by xcross is compiled into user apps; until upstream grants an explicit exception for
  generated output, this is documented as a known licensing question. Fork-authored templates carry an explicit
  output exception.
- A legal review is required before the 1.0 release.

## Development Workflow & Quality Gates

- Every feature follows Spec Kit: `/speckit-specify` → `/speckit-clarify` → `/speckit-plan` → `/speckit-tasks` →
  `/speckit-implement`, in `specs/NNN-slug/` (`spec.md`, `plan.md`, `tasks.md`, `research.md`, `device-check.md`).
- Branches and PRs are named `NNN-slug`. CI runs on `ubuntu-latest` and `windows-latest`; a spec-lint job requires all
  `tasks.md` boxes to be ticked before merge.
- **Definition of done:** all ACs checked; unit and golden-IPA tests green on Windows and Linux; device evidence from
  both hosts on an iOS 16 device (iPhone X) and an iOS 17+ device for device-affecting features; docs and CHANGELOG
  updated; upstream PR linked when the change is upstreamable.

## Governance

This constitution supersedes other practices in this repository. Every spec, plan and PR review checks compliance;
deviations must be justified in the feature's `plan.md` under "Complexity Tracking". Amendments are made by PR that
updates this file, bumps the version (MAJOR: principle removed or redefined; MINOR: principle or section added;
PATCH: wording), and records the change in the Sync Impact Report.
